主仓库的 `docs/design/` 只保存已批准的架构与产品设计，回答“系统应当如何工作”。它不记录调查、迁移批次或完成清单；现行行为由代码、契约测试和复现证明。

状态只有三种：现行设计表示已落地；已批准目标表示尚未完全落地，进度写 `spec/issues/`；待重构表示目标已收敛、实现差距已审计。

## 维护边界

1. 新设计先确定状态、scope、代码事实源和对应 active issue。
2. 实施完成后删掉进度叙事，只把稳定结果同步为“现行设计”。
3. 文件改名、合并或删除时，同步根/模块路由、standards、code-index 与 active spec 引用。
4. 动态 inventory、固定源码行号和命令输出不复制进设计；定位信息放 `docs/code-index/`。

## 事实源

本页是贡献者入口，不替代主仓库文档。发生冲突时，按代码与契约测试、`docs/standards/`、模块指引、`docs/design/`、active spec、历史记录的顺序判断。
