Peri 可以由 Agent 注册、列出和删除重复任务。你通常只需用自然语言描述任务；Agent 会在后台调用 cron 工具。

```text
每个工作日 UTC 01:00 提醒我查看 CI 状态。
列出当前的定时任务和完整 ID。
删除 ID 为 <完整 UUID> 的定时任务。
```

## 时间语义

调度器使用 **UTC** 和 5 字段 cron 表达式：

```text
分 时 日 月 星期
```

| 需求 | 表达式 |
| --- | --- |
| 每 5 分钟 | `*/5 * * * *` |
| 每天 UTC 09:00 | `0 9 * * *` |
| 每周一 UTC 10:00 | `0 10 * * 1` |
| 每月 1 日 UTC 00:00 | `0 0 1 * *` |

“早上 9 点”没有时区信息，容易注册成错误时间。请明确写 UTC，或先自行换算。例如中国标准时间 09:00 对应 UTC 01:00，表达式为 `0 1 * * *`；夏令时地区需要额外考虑季节变化。

## 生命周期

当前 cron 调度器是**进程内存状态**：

- 只有交互式 TUI 宿主会驱动 cron tick；`peri -p` 不会。
- 关闭或重启 Peri 后，已注册任务会丢失。
- Peri 未运行时不会被系统唤醒，也没有补跑错过任务的 catch-up 机制。
- 触发时会把保存的任务描述提交给会话执行；它不是操作系统的 `cron` 服务。

<Aside type="caution">
  不要用当前 cron 承担备份、证书续期或生产告警等必须可靠执行的任务。此类任务应由操作系统或专用调度服务负责，再按需调用 Peri。
</Aside>

## 管理与 ID

任务列表的展示文本可能只显示 ID 前 8 个字符，而删除接口当前按完整 ID 精确匹配。要求 Agent 列出并使用完整 ID；如果界面只给出短 ID，删除可能失败，这是当前版本的已知限制。

注册 cron 属于会产生后续工具调用的操作。请检查任务描述、权限模式、工作目录和可用凭据，避免把宽泛指令长期留在一个高权限会话中。
