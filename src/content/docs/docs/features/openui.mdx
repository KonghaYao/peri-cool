## 是什么

OpenUI 是 Peri 的一种助手输出格式。模型不再只写 Markdown，而是给出一段声明式程序，客户端把它渲染成指标卡、表格、图表、任务清单等界面。

同一段程序在 Web 会话里是界面，在终端（TUI）里仍是文本。这是两端渲染能力的差异，不是模型输出的差异。

## 什么时候会出现

Peri 判断「表格或图形比长段文字更容易读」时会使用 OpenUI，常见场景：

1. 多指标汇总：订单量、退款率、准时率并排展示。
2. 结构化明细：按城市、模块或版本对照的数据表。
3. 趋势与分布：折线图、柱状图、饼图。
4. 任务状态：清单、进度、改动文件列表。

是否输出 OpenUI 由模型决定；你可以直接要求「用 Markdown 回答」来得到纯文本。

## 示例

下面的面板由本页直接渲染，数据是演示用的，不是真实会话：

<OpenUI
  title="示例：三项指标"
  program={`root = Stack([headline, metrics, basis])
headline = H2("本周处理量上升 12%")
metrics = Grid(3, [orders, refunds, onTime])
orders = Stat("2,702", "订单量", "success")
refunds = Stat("34", "退款单", "warning")
onTime = Stat("96.4%", "准时率", "info")
basis = Text("来源：演示数据；对比前 7 天。", "secondary", "small")`}
/>

展开「查看 OpenUI 源码」可以看到模型实际输出的程序。本页使用的是 Peri Web 客户端同一套渲染器，水合后配色跟随站点明暗主题；水合完成前显示服务端生成的浅色静态版本。

## 怎么用

不需要手动写 OpenUI 程序。你描述任务，Peri 自行决定是否输出，例如：

```text
你: 把上周各城市的订单、退款和准时率整理一下，能对比的用表格

Peri: [输出 OpenUI 程序]
      [Web 客户端渲染为标题 + 表格 + 结论]
```

## 限制

1. 目前只有 Web 会话渲染 OpenUI；TUI 会把程序按原文显示。
2. 本页是静态展示，表单控件和按钮处于禁用状态，点击不会回传到对话。
3. 程序必须完整并通过校验；解析失败时客户端回退显示原文，不会白屏。
4. 界面由服务端渲染为静态 HTML；关闭 JavaScript 时仍能看到界面，但无法交互（本页控件本来也处于禁用状态）。
5. 卡片和图表使用 OpenUI 自带的配色令牌，不会逐项套用站点的 `--nb-*` 样式。
