主 Agent 与多个子代理并行输出时，事件到达次序不等于执行层级。某个子代理的文本可能晚于主 Agent 的下一阶段到达，旧会话的终止事件也可能晚于新轮次。消费端若从时间顺序猜来源，渲染、观测和过期事件过滤都会出现分歧。

Peri 把身份分成两层。**源事件身份**在 Agent 发射时固定当前轮次与来源 Agent，**事件封装层**在运行时与控制器聚合时补充会话标识与会话内顺序。封装结构也预留了会话代际字段，但生产路径尚未接通跨实例递增。两层解决的问题不同，不能压成一个由任意消费端填写的字段集合。

## Agent 固定轮次与事件来源

Agent 最清楚事件属于哪个轮次，也知道事件由主 Agent 还是子代理产生。因此第二版事件在源头强制携带轮次标识和 Agent 标识，渲染、状态和观测三类事件都使用同一约束。

让 ACP 或 TUI 根据当前活跃卡片补来源不可靠。并行输出会交错，卡片栈顶只能表示最近处理了谁，不能证明下一条事件来自谁。后台任务跨轮次存活时，这种近似更容易失效。

源层也不应生成会话顺序。Agent 可以产生业务事件，却不掌握某个会话的全局聚合位置。把会话序号分散到多个生产者，会产生重复或倒退。

## 聚合层补充会话与顺序

运行时持有会话映射和会话内序号，因此负责给源事件补上会话标识、会话代际和单调序号。控制器的统一发布入口接收源身份与协议事件，补齐这些字段后再投递到弹出队列和订阅广播。

会话内序号给去重和排序提供稳定依据。它表达的是聚合顺序，不应被解释成不同 Agent 的真实完成时间。会话代际字段当前仍使用初始值，跨实例递增属于尚未接线的恢复边界，因此它目前不能承担迟到事件隔离保证。

会话已销毁或未注册时，控制器无法取得正常的聚合状态。当前路径会使用发射方身份和初始会话字段继续投递，而不是让进程崩溃。这是迟到事件的降级路径，不能据此承诺所有异常事件仍有完整的全局单调序号。

## ACP 映射只透传已有归属

事件进入 ACP 后会转换成客户端协议更新。子代理的来源 Agent 标识作为路由提示继续传递，主 Agent 没有子代理来源时保持空值。映射层不根据事件内容或到达位置重新推断来源。

早期架构曾存在多条发射与投递路径。同一语义可能从两条路径到达 TUI，身份字段也可能只在其中一条被补齐。当前契约要求 Agent 的第二版事件成为单一事实源，ACP 保留协议化所需的最小兼容映射，不再恢复第二套直连投递。

完全删除兼容载体也不是当前选择。外部传输格式仍需要稳定的协议映射，关键约束是兼容层只做序列化，不重新成为业务事件事实源。

## 测试覆盖身份和映射链路

Agent 事件测试检查各事件强制携带轮次与来源身份。身份类型测试检查事件封装的序列化和会话序号契约，控制器测试检查发布时补充会话信息。

ACP 映射测试分别覆盖主 Agent 与子代理来源，变体覆盖测试防止新增事件静默落入未映射分支。目标测试按事件源、聚合层和协议层分开执行，避免某一层的类型检查替代完整链路验证。

这些测试证明仓库内事件链的身份契约，不证明网络传输绝不丢包，也不把会话序号等同于墙钟时间。观测系统仍要显式处理缺失终止事件与慢消费者，TUI 也要决定迟到事件的具体显示策略。

开头那些交错到达的主 Agent 与子代理事件不再需要消费端猜测。来源在 Agent 层确定，会话位置在聚合层确定，后续组件只消费已经建立的身份。
