## 按 patch 看

### 4.1.0（10-17 09:39，4 个提交）

1. `#221` Full Compact 后的历史分页与 transcript 收缩；`#234` 子代理工具面全量继承；`#235` 工具证据与回执；`#236` workflow 子会话结清。

### 4.1.1（10-18 23:26，6 个提交）

1. `#237` 重试上限与 goal 恢复；`#238` historyWindowV1；`#239` 默认委派与只读 `explorer`；`#240` 工具审计；`#241`/`#242` 历史窗口边界与复审修复。

### 4.1.2（10-19 16:41，6 个提交）

1. `#243` MCP 详情表；`#244` 后台 shell 并发 5 → 20；`#245` MCP 数据边界；`#246` 依赖与工具链升级。

## 在项目阶段中的位置

1. 4.1 仍在第二段「单机服务化」；本版处理上下文所有权、子代理委派与 MCP 数据边界。
2. 不把本版写成服务化完成：托管部署、跨实例接管、真实云端验收仍未进入 tag。
3. 版本线到阶段的对应是归纳；根 `CLAUDE.md` 只划分三阶段。

## 未完成项与证据边界

1. `#221` 的提交正文自报 4 项遗留：A05 索引待裁决、`peri.sessionWorkspaceV1` 门控待裁决、锁调用点级绕过缺口、WASM 红绿链不可独立复核。本页不据此写成已验收。
2. 仓库另有分支提交 `5e691a2ac` 记录 A05 与 sessionWorkspaceV1 的后续裁决，但它不在 4.1.0 的 tag 历史里；本页不把它当作 4.1.0 的内容。
3. tag 日期不是发布日；没有 GitHub Release、制品构建结果与 npm 状态。

## 升级注意

1. 子代理读写硬限制消失，工具面全量继承；小任务也可能被拆分，是否拆分由模型按独立性、风险与验证成本判断。
2. 后台 shell 并发上限 20；资源占用可能上升。
3. ACP 历史分页需要客户端协商；未协商的客户端仍收到完整历史回放。
