这份项目更新覆盖 2026-08-23 至 2026-10-16（约 8 周）的仓库证据窗口。窗口内共 396 个提交、42 个 tag、3 份月度日志。

1. 本文只写使用者能观察到的变化，不写内部实现清单。
2. 尚未进入任何 tag 的能力单独标注，不与已发布版本混写。
3. 数字与状态词按仓库原文引用，口径见文末「证据口径」。

## 版本线：3.19.4 到 4.0.8

1. `agent-v3.19.4` 是 `main` 线最后一批，tag 时间 2026-09-29。
2. `agent-v4.0.0` 的 tag 时间是 2026-10-11，指向 v4 分支合并回主线的合并提交。
3. 这次分界只有 11 个提交（含 1 个合并提交），但包含了工具迁移、存储改造、界面重建等大批量改动，不能把 11 当作改动量。
4. `agent-v4.0.0` 到 `agent-v4.0.8` 之间有 68 个提交，`agent-v4.0.8` 的 tag 时间是 2026-10-15。
5. tag 时间只是打标记的时刻，不等同于安装制品对公众可用的发布时间。

## 工具与 MCP

1. 【变更】七个文件与终端工具（`Read`、`Write`、`Edit`、`Glob`、`Grep`、`folder_operations`、`Bash`）改由内置 `workspace` 实例承载，**模型面的工具名保持原名**。
2. 【变更】system MCP 工具不再带 `mcp__<server>__` 前缀；同名冲突改为告警加先到者生效，旧行为是启动失败。
3. 【新增】`workspace` 实例新增 `skill://`、`agent://`、`peri-instruction://`、`peri-meta://` 四类资源域，Skill 与子代理定义从文件系统下沉为 MCP 资源。
4. 【移除】LSP 能力整体删除：工具面、配置键与相关模块一并移除，没有保留兼容层。
5. 【移除】`local-mcp-server` 退役。
6. 【新增】Workflow 编排改为内置 MCP 实例，工具以 `mcp__workflow__*` 出现，属于延迟发现工具。
7. 【变更】自写 Node workflow 的 wire 契约由请求响应改为任务通告与结果回填，需要同步对应包。
8. 【变更】Git Watch 改为经订阅与资源更新通知回传。已知收窄：非 `workspace` 工具造成的 git 改动，要等到下一次 `workspace` 调用才可见。
9. 【变更】Edit 与 Write 的工具描述里，「未先 Read 的写入会失败」这条硬承诺被移除。
10. 【修复】修复了 ACP 请求顶层附件的图片输入在主执行路径静默失效的问题。
11. 【修复】修复了恢复子代理后新消息归入旧调用分组的问题。
12. 【修复】修复了 Micro Compact 之后模型读不到本轮用户图片的问题。

## 存储与会话

1. 【新增】存储 v2：Machine、Workspace、Session 三级归属与归档落地，MCP 授权与响应缓存按工作区隔离，详见[会话归属三层模型](/posts/engineering/session-ownership/)。
2. 【新增】Turso 远端存储：使用远端定位符时，会话、绑定与证据只走远端，不再打开或创建本地库。
3. 【变更】会话库代数压缩：v4 期间推进到 19 的中间代被收敛为紧接正式基线的单条迁移。正式版 `agent-v3.19.x` 对应 10，`agent-v3.18.0` 对应 6，当前代码常量为 11。
4. 【移除】随新代数同事务删除两张表与两列，删除对象属于执行记录与旧上下文缓存。
5. 【变更】持久执行恢复被剥离：重启后可加载历史会话并续聊，但不恢复旧执行，详见[重启不恢复执行](/posts/engineering/restart-no-recovery/)。
6. 【变更】OAuth 凭据迁入配置库，旧的 JSON 文件不迁移。
7. 【移除】会话 sidecar 文件锁删除，改为持久机器身份与按 ID 恢复。
8. 【修复】升级到 `agent-v3.15.0` 后旧 history 不可见、无法恢复的问题。
9. 【修复】异常退出后 history 无法恢复（报前一执行未干净关闭）的问题。
10. 【修复】长会话中完整压缩与微量压缩反复交错、显示「节省约 0 token」的问题。
11. 【修复】完整压缩遗漏系统通知里的子代理报告，压缩后仍占用约一半上下文的问题。
12. 【修复】微量压缩截断写入类历史参数并向模型注入伪源码的问题，该缺陷存在写入数据损坏风险。

## 配置与命令行

1. 【新增】配置权威面：类型化的配置装配、作用域与修订号、不可变快照发布。
2. 【新增】`config.betas` 配置面与界面的 Beta 区块，首个开关是「全异步工具」：Bash 与子代理在调用未显式指定后台时缺省走后台，显式指定前台仍然生效；不配置该项时行为与旧版一致。
3. 【移除】环境变量 `PERI_WRITE_DRAFT` 移除。
4. 【变更】模型选择不再由单个变量带厂商回退，改为成对给出 provider 与档位。
5. 【变更】`--settings` 不再写固定路径的临时文件，改为内存装配，避免了并发覆盖与敏感配置留痕。
6. 【新增】`peri mcp-start workspace`：启动独立的纯 MCP 工作进程，stdio 与 HTTP 共用同一处理器。该能力自陈状态为「开发中」，文档未登记，慎用。
7. 【新增】外部系统指令改为独立的冻结字段，在主会话、子代理与工作流请求边界统一组合。

## 界面

1. 【变更】TUI 工作台在 v4 数据流上重建。
2. 【变更】过程区的连接几何定案为一行台阶加圆角，已按该形态落地。
3. 【修复】子代理活跃流式输出期间 CPU 占用约 150%–170% 的问题。
4. 【修复】长 Markdown 流式输出导致 CPU 占用升高的问题。
5. 【修复】print 模式在后台命令大输出完成后无法结束的问题。
6. 【修复】print 模式在可见流增量后中断时直接终止、不保留部分输出的问题。
7. 【修复】空闲提交先闪过待发送队列、队列输入框边线间隙、新会话状态延迟约 1 秒、空闲后不自动发送队首输入等一批显示与状态问题。
8. 【进行中】TUI 面板架构重构尚未进入任何 tag，等正式版本发布后再看。

## 平台与发布

1. 【新增】Langfuse 遥测 spool：上报不阻塞业务等待。该条目状态为「已实施，待用户验收」，并自报格式检查未通过、真实端点与积压内存未执行。
2. 【修复】Windows 上发送请求后静默卡死的问题，定位为等待一个 git 子进程返回。
3. 【新增】WASM 接入：Emscripten 目标编译完成，Node、Bun 与本地 workerd 验收通过；**托管部署尚未验收**，WASM 场景下文件工具需由外部 MCP 提供，详见[嵌入与 WASM 契约](/posts/engineering/embedding-wasm/)。
4. 【变更】发布资产命名与安装契约：归档根内直接放可执行文件，每个资产带校验文件与汇总清单；旧版归档名不同，安装脚本保留回退分支。
5. 【变更】`peri update` 复用安装脚本；mise 安装需要带 `agent-v` 前缀的版本号。
6. 【移除】README 的 beta 安装段落被移除，beta 安装脚本与产物仍然存在。

## 升级需要注意的事

1. **会话库会迁移**：升级到 4.x 会走一次单条迁移。仓库没有给出备份提示，升级前请自行备份会话库。
2. **部分库对象会被删除**：迁移同事务删除执行记录与旧上下文缓存相关的表与列。
3. **恢复语义收窄**：重启后能加载历史并续聊，但不恢复旧执行。
4. **环境变量变化**：`PERI_WRITE_DRAFT` 移除；模型选择改为 provider 与档位成对给出。
5. **LSP 能力消失**：不是改名，是把整块能力删除，原有 LSP 工具调用不再存在。
6. **工具名总体不变**：七个文件与终端工具仍是原名；system MCP 工具不再带前缀，重名按先到者生效并告警。
7. **Workflow 用法变化**：改为经 MCP 实例发现与调用；自写 Node workflow 需要同步 wire 契约。
8. **写入不再要求先读**：Edit 与 Write 的工具描述去掉了这条限制说明。
9. **遥测用户注意**：遥测 spool 待验收，且报告里自报格式检查未过、真实端点与积压场景未执行。
10. **无服务器用户注意**：WASM 产物不打包 workflow；部署形态下的文件工具需要外部 MCP。

## 什么是这段时间的主线

1. 工具从宿主直连搬进内置 MCP 实例，工具环境与计算实例开始分开。
2. 存储从本机走向远端，会话归属升级为机器、工作区、会话三级。
3. 执行恢复被剥离，会话、任务运行与计算实例各自持有独立生命周期。

代价同时出现：升级要迁库，LSP 这类能力直接消失，部分新能力（WASM 托管部署、遥测 spool）还没有验收完成。

## 证据口径

1. 提交数按 `git log --since/--until` 统计：整段口径（自 08-22 起算）为 396，自 08-23 起算为 386；本文以 396 为准，未做约化。
2. 状态词直接引用 issue 与月志原文：「已实施，待用户验收」「开发中」不写成「已修复」。
3. 月度日志是压缩产物，其状态是记录时刻的状态，不代表现行事实；「已修复」类结论均回到 issue 原文或提交核对。
4. 仓库没有维护中的变更日志，变更日志文件停在 2026-06-02。
5. 未取得的项：真实 Release 发布时间、远端分支的当前状态、各平台产物的构建结果。
6. 引用当前工作区文件的结论可能超前于任一已发布版本：采集时的检出点比 `agent-v4.0.8` 多 38 个提交。

回到这 8 周的窗口，用户可见变化集中在三件事上：工具接入方式、会话存储位置、重启后的执行语义。需要动手的地方只有两处：升级前备份会话库，检查是否有依赖 LSP 或旧环境变量的用法。
