Peri v2 阶段的关键变化，是把 Agent 执行与终端界面之间的交互收敛到 ACP 边界，让 TUI 不再直接复制 Agent 业务逻辑。

</Aside>

## ACP 边界

ACP 提供 session、流式更新、工具调用与权限请求等协议结构。同一 Agent 核心可以通过内存 transport 连接 TUI，也可以通过 stdio transport 服务外部客户端。具体客户端仍可能只实现协议的一部分，不能从“支持 ACP”推导出所有功能一致。

## TUI 分层

v2 的 TUI 使用 ratatui-kit 组织组件、路由和状态，负责渲染与交互；会话与 Agent 执行留在后端层。流式 Markdown、面板和后台任务状态由协议事件驱动，但各面板仍有不同的读写能力。

## Workflow 与子代理

这一时期 Workflow 与 SubAgent 成为复杂任务的主要组织方式。Workflow 使用显式状态与 journal 记录运行进度，SubAgent 提供独立上下文；两者都不意味着任意任务能够自动恢复或确定性重放，恢复边界以当前实现和测试为准。

## 升级边界

仓库证据可以说明 v2 的架构变化，但不足以支持旧文中“配置格式不变、二进制路径和内部存储不同”的完整迁移承诺。升级前请备份 settings 与会话数据库，按当前[安装指南](/peri-cool/docs/get-started/installation/)重新检查路径和依赖。
