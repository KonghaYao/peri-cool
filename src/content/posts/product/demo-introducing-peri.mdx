Peri 是一个用 Rust 编写、运行在终端中的 AI 编码助手。它提供交互式 TUI，同时把 Agent 循环、协议装配和扩展中间件分开维护。

这篇文章最初用二进制大小、内存、缓存命中和代码生成比例介绍产品。那些数字没有附带可复现的公开基准，无法支持跨版本或竞品比较，因此不再作为产品承诺。判断 Peri 是否适合你的项目，更可靠的方法是看它的边界与验证方式。

## 产品主路径

一次交互通常经过：

```text
peri-tui → peri-acp → peri-agent::run_react_loop
```

- TUI 接收输入、展示事件并提供状态面板。
- ACP 层装配会话和中间件，并把内部事件映射到协议更新。
- Agent 负责模型请求、工具调用、上下文压缩与退出判断。
- MCP、plugins、skills、hooks、HITL 和 workflow 由中间件层接入。

这种分层的价值不是自动带来某个性能数字，而是让协议、界面和执行循环拥有可测试的边界。

## 模型与配置

Peri 支持 Anthropic 以及 OpenAI-compatible 的 provider 路径。兼容端点是否支持工具调用、图片、流式响应和特定推理参数，仍由服务端与模型决定。

四个模型档位把“当前任务需要的能力层级”与具体模型名分开。切换档位可以通过 TUI Model 面板完成；不要假设所有 CLI 覆盖参数都已接线，命令行为以[参考页](/peri-cool/docs/features/cli-reference/)为准。

## 扩展生态

Peri 可以读取和装配 Claude 风格的 skills、agents、hooks 以及 MCP 配置，但“能够读取相同格式”不等于所有第三方扩展行为完全相同。事件支持、终端交互、工具名称和权限链都需要在当前版本中验证。

<Aside type="caution">
  无参数启动当前默认使用 Bypass。它会跳过 Peri 的工具审批，但不提供 OS 沙箱。第一次在真实仓库使用时建议运行 <code>peri --permission-mode default</code>，并保持工作区可回滚。
</Aside>
