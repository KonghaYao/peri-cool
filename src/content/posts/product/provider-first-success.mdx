第一次打开 Peri，设置向导会引导用户填写 Provider、API Key 和四个模型档位。向导中的连通检查通过后，第一条真实消息仍可能失败，因为网络可达、配置保存和模型生成是三层不同证据。

首次成功的标准很具体。重启 Peri 后，在 `/login` 核对 Provider，在 `/model` 核对当前档位与本地模型映射，最后发送一条最小请求并收到模型回复，才算走完整条链路。

## 连通检查只探测网络入口

设置向导里的 **连通检查** 会解析 Base URL，建立 TCP 连接，再向对应路径发送一个不带凭据的 HTTP 请求。它能发现 DNS、端口或基础网络不可达，不能证明 API Key 有效，也没有调用模型生成接口。

这一区别对自定义 OpenAI-compatible 服务尤其重要。一个地址可以正常响应普通请求，同时拒绝鉴权、找不到配置中的模型名，或者不支持 Peri 随后使用的生成协议，所以连通结果只能作为网络层证据。

## 向导完成后重启运行时

向导完成页会把配置保存到磁盘并关闭。当前这条保存路径不会像 `/login` 和 `/model` 那样同步刷新正在运行的 Provider 与会话配置，因此完成向导后应退出并重新启动 Peri。

保存动作本身也不能当作成功回执。当前保存失败主要写入 tracing 日志，向导仍会关闭，用户界面不保证展示可操作的错误，因此重启后的配置核对与真实请求不可省略。

## Provider 面板核对连接材料

重启后输入 `/login`，先检查刚配置的 Provider 是否出现在列表中。进入详情后核对类型、ID、Base URL、API Key 和四个模型档位，发现错误可以在这里修改并保存，保存路径会同步更新当前运行时。

Provider ID 是档位映射引用的名字，不是服务端账户名。删除或改名后还要检查 `/model` 中的档位映射，避免档位仍指向已经不存在的 Provider。

## 模型面板核对本地映射

输入 `/model` 后，左侧显示 fable、opus、sonnet、haiku 四个档位。上下移动会切换当前档位，进入右侧后可以调整 Provider、模型、effort、输出上限和上下文选项，改动会立即保存并推送到当前配置。

模型候选来自本地 Provider 配置，不是从服务端实时拉取的模型目录。面板中出现一个模型名，只能证明本地映射存在，不能证明远端端点接受这个名字。

## 最小请求验证完整生成链路

配置核对完成后，发送一个不需要工具和仓库上下文的最小请求。下面的输入输出是演示示例，不是真实会话。

```text
用户
只回复 READY，不要读取文件，不要调用工具。

Peri
READY
```

收到回复说明当前 Provider、凭据、模型映射和基础生成接口已经共同工作。若请求失败，先按错误层排查，鉴权错误回到 `/login` 检查 Key，模型不存在回到 `/model` 检查映射，协议或端点错误再核对 Provider 类型与 Base URL。

这个最小请求没有验证工具调用、图片输入或长上下文兼容性。它只建立第一次文本生成的端到端证据，后续能力仍应按实际任务分别验证。

## 首次成功以可观察结果收束

回到第一次打开向导的场景，绿色连通状态只是网络入口可达。重启后的面板核对和一条真实回复，才把磁盘配置、运行时映射与模型服务接成可观察的闭环。

继续阅读 [Provider 配置](/peri-cool/docs/guides/providers/) 和 [模型档位](/peri-cool/docs/features/model-profiles/)。遇到失败时，可按 [故障排查](/peri-cool/docs/troubleshooting/) 回到对应证据层。
